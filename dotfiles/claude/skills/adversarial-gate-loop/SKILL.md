# 적대적 이중 게이트 검수 루프

산출물을 두 외부 리뷰어로 번갈아 두드려 **BLOCKING 0건**까지 수렴시키는 워크플로.
Fable(이 세션)이 작업자·판정자, codex sol이 1차 적대 리뷰어, ChatGPT Pro가 최종 게이트다.

## 큰 흐름 (사용자 확정 규칙)

1. **sol 게이트**: sol 적대 리뷰 라운드를 BLOCKING 0건(CLEAN)까지 반복한다.
2. **Pro 게이트**: CLEAN 상태를 홈서버 `gpt-webai-pro`(ssh home, 전역 gpt-delegation.md 정본 경로)로 보낸다. blocker가 나오면
   → Fable이 판정·반영 → **sol 회귀 검증 라운드 CLEAN** → 다시 Pro.
3. **Pro `<verdict>LGTM</verdict>`(0건)까지 반복. LGTM 없이 완료 선언 금지.** sol CLEAN은 중간 상태다.
4. Pro 왕복은 수 시간이 든다. Pro 대기 중 산출물을 건드리지 않는다(판정 대상이 바뀐다).

## 라운드 프로토콜 (sol·Pro 공통)

- 매 라운드는 **fresh 리뷰어**다. 프롬프트에 반드시 넣는다:
  (a) 산출물 배경과 읽기 순서, (b) BLOCKING/NON-BLOCKING 판정 기준,
  (c) **직전 라운드 blocker별 처리표**(반영 내역 또는 기각+사유),
  (d) "기각 항목을 같은 논거로 재제기하지 말고 처리 검증과 신규 발굴에 집중하라",
  (e) 출력 형식: 교정 검증 절 + BLOCKING 목록(파일:위치/문제/근거/확인 방법) + 마지막 줄
      `<verdict>CLEAN|LGTM</verdict>` 또는 `<verdict>BLOCKERS</verdict>`.
- **리뷰어에게 파일 수정 금지 + "재현은 저장소 밖 임시 복제본에서만"을 명시**한다.
  (실증 사고: sol이 재현 중 원본을 오염시킨 적 있음. 라운드 후 원본 git status·fsck 확인.)
- 리뷰 결과는 그대로 믿지 않는다. **항목별로 Fable이 실물 재검증** 후 3분류한다:
  실질(반영) / 오탐(기각+사유 기록) / 기준 밖(기각). GPT·sol 모두 과잉 보수 성향이 있어 이 필터가 필수다.

## 판정할 때 깨져본 것들 (오탐·확대해석 방지)

- **파일 조각이 아니라 유효 상태로 판정한다.** 리뷰가 지목한 줄만 보지 말고, 대체·상속·기본
  컬럼까지 합친 최종 상태를 본다. (실증: PASS 행이 결함으로 보였으나 기본 컬럼이 이미 전부 포함)
- 정규식·휴리스틱으로 훑은 내 검증 결과도 오탐일 수 있다 — 판정 전 원문 재확인.
  (실증: 문서지도 표가 표기 차이로 "누락"으로 보임, D-101 검사 범위 오판)
- 설계 의도(예: 원장이 대체관계를 소유)는 결함이 아니다. 근거 문서를 확인하고 기각한다.

## 비수렴 차단 — 기준 확정 (필수)

fresh 리뷰어는 라운드마다 같은 차원을 한 층씩 더 파며 무한히 blocker를 만든다
(실증: 라운드 12~20 동안 검증기 강화 요구가 3→3→5→2→1→…로 이어짐). 대응:

1. blocker 수가 2라운드 연속 줄지 않거나 같은 클래스가 반복되면, 문장별 대응 대신
   **클래스 전체를 구조적으로 닫는다** (실증: 원장 문장 변조 7종 → 파일 SHA-256 서명 도입으로 일괄 폐쇄).
2. **방어 장치 자체가 blocker 공급원이면 장치를 빼는 것도 클래스 폐쇄다.** Git으로 관리되는
   산출물에 자체 무결성 층(파일 해시 서명·검증 결과 바이트 고정점·파일 개수 계약)을 만들지
   마라 — Git 커밋 해시와 중복이고, 그 장치가 막는 공격자는 검사기 자체를 고칠 수 있으며,
   fresh 리뷰어가 매 라운드 그 장치의 빈틈만 파는 비수렴을 만든다 (실증: RouteFork DA-10에서
   서명 도입 후 3라운드 연속 blocker 10건이 전부 장치 자체에서 나와 사용자 판정으로 제거).
   검증 자동화는 내용(의미) 검사로 한정한다.
3. 방어 불가능한 전제는 **기준에서 명시적으로 제외**하고 산출물에 기록한다.
   (실증 문구: "검증기 파일 자체 변조·Git 이력 조작·운영자의 악의적 CLI 오용을 전제한 지적은
   NON-BLOCKING — 그 전제의 공격자는 검사를 직접 지울 수 있어 검사 추가로 방어되지 않는다.
   Git 서버·사람 리뷰가 방어 경계다.")
4. 제외 목록은 매 라운드 프롬프트의 "재제기 금지"에 누적한다.

## 라운드 프롬프트 골격 (복붙용)

```markdown
너는 <산출물>의 **적대적 리뷰어**다. **파일 수정 금지 — 재현은 반드시 저장소 밖 임시 복제본에서만.**
<N>라운드 — 라운드 <N-1> 교정의 회귀 검증(수렴 판정).

## 라운드 <N-1> 처리 결과
- B<N-1>-1 반영: <무엇을 어떻게>. <검출 확인 내역>.
- B<N-1>-2 기각: <사유>.

## 검토 기준 (확정본 유지)
BLOCKING = (a) 사실 모순·깨진 참조, (b) 확정 결정 왜곡·증발, (c) 거짓 승인·증거,
(d) 검사기가 통과시키는 실제 결함 — <방어 경계 밖 전제> 제외, (e) 인수인계 오도,
(f) 정당한 절차를 차단하는 기능 버그. 재제기 금지: <누적 목록>.

## 임무
교정 완결성 검증(임시 복제본 재현), 새 모순 수색, 검사기·Git 상태 확인.

## 출력 (한국어)
### 교정 검증
완결 | 미완결(근거)
### BLOCKING
[B<N>-n] 파일:위치 — 문제 / 근거 / 확인 방법 (없으면 "없음")
### 마지막 줄
`<verdict>CLEAN</verdict>` 또는 `<verdict>BLOCKERS</verdict>`
```

## 검사기(gate) 자체를 고칠 때 — 돌연변이 테스트 관행

리뷰어가 "이 결함이 검사를 통과한다"고 재현했으면, 고친 뒤 **같은 공격을 임시 복제본에서
재현해 검출되는지** 확인한다. 정상 케이스(예: 정당한 후속 항목 추가)가 여전히 통과하는지
**양성 테스트**도 함께 돌린다. 검출 결과를 산출물의 검수 기록에 남긴다.

하네스 골격 (rsync 복제 → 변이 적용 → 검사기 실행 → 검출 여부):

```bash
run_case() {  # $1 라벨, $2 변이 셸코드
  rm -rf /tmp/mut && mkdir -p /tmp/mut && rsync -a <저장소>/ /tmp/mut/ --exclude .git
  ( cd /tmp/mut && eval "$2" )
  N=$(cd /tmp/mut && <검사기 명령> 2>&1 | grep -c "FAILED")
  echo "$1 → $([ "$N" -gt 0 ] && echo 검출 || echo '!!!미검출')"
}
```
- 미검출이면 즉시 원인 디버그: 파서가 그 형태를 아예 못 잡는 경우가 흔하다
  (실증: 빈 셀 행이 정규식 공백 요구와 안 맞아 파싱 자체에서 누락).

## sol 실행 방법 (로컬 맥 기준)

```bash
# 반드시 detach — 감시 루프와 같은 프로세스 그룹이면 감시자가 죽을 때 codex도 죽는다 (실증 사고 2회)
nohup ~/.local/bin/codex exec -C <저장소> -m gpt-5.6-sol -c model_reasoning_effort='"max"' \
  -o <라운드보고서.md> - < <라운드프롬프트.md> >| <라운드로그> 2>&1 &
disown
# 감시는 별도 백그라운드 태스크에서: 보고서 파일 생성 폴링 + 로그 mtime 5분 정지 시 stall 판정
```
- **프롬프트 어휘 주의**: "뚫는다·우회·변조·공격" 같은 공격 어휘가 누적되면 업스트림의
  사이버보안 필터가 리뷰 turn을 중간에 차단할 수 있다 (실증: 183K 토큰 진행 후
  "flagged for possible cybersecurity risk"로 사망). 같은 임무를 품질 검수 어휘로 쓴다 —
  "검출 누락", "회귀 시험", "정본 불일치 시험", "돌연변이 시험(양성/음성)". 차단되면
  재현이 아니라 어휘 문제이므로 QA 표현으로 재작성해 재실행한다.
- effort는 사용자 지시로 **max** (`~/.claude/rules/codex-lb-models.md`).
- 네트워크 전환 중 조용히 멈출 수 있다(프로세스 생존 + 로그 정지). stall이면 죽이고 재실행
  (리뷰는 재실행 안전). 한국어 산출물 언어 규칙도 같은 rules 파일 참조.

## Pro 게이트 실행 방법

홈서버 `gpt-webai-pro`로 전송한다 (zip 첨부, detach 실행 — 전역 gpt-delegation.md). 번들 구조(재현성 — Pro가 실제로 요구했던 형식):

```
번들.zip
├── MANIFEST.md          # 구성·읽기 순서·재현 명령·이번 판정 대상
├── baseline/            # 산출물 순수 트리 (.git 제외; Git 커밋·tree 해시는 MANIFEST에 명기)
└── _review/             # sol 라운드 보고서 전부 + 이전 Pro 라운드 원문 + git 이력 텍스트
```
- MANIFEST의 재현 명령이 **실제로 통과하는지 전송 전에 스모크**한다.
- secret 절대 금지, `.git`·빌드 산출물 제외 (전송 전 secret 스캔).
- 전송·회수 함정(장시간 대기는 실패 아님, 재전송 금지·resume만)은 전역 gpt-delegation.md와 ~/.codex/runbooks/gpt-webai-pro.md가 소유.

## 수렴 후 마무리

1. 최종 상태로 재포장(zip 등) → **재해제 스모크**(새 폴더에 풀고 게이트 전체 재실행) → 납품.
2. 산출물 안에 라운드별 발견·교정·기각 기록을 남긴다(다음 세션의 재제기 방지 근거).
3. 다음 세션이 콜드 스타트로 이어받을 수 있게 산출물 안에 런북(수정 절차·루프 규칙·다음 안건)을 둔다.
   메모리는 작업 폴더가 바뀌면 읽히지 않으므로 쓰지 않는다 — 산출물·스킬·rules에 남긴다.
